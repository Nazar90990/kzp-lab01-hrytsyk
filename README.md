# Лабораторна робота №1: Комунальні показники

Консольна Java-програма читає показники комунальних послуг, пропускає хибні записи з поясненням причини, обчислює показники та створює звіт у консолі й файлі.

## Формат входу

Файл кодується UTF-8. Один запис займає рядок, поля розділені `;`:

```text
meter;date;value;tariff
```

Дата є текстом у форматі `YYYY-MM-DD`. Числа `value` і `tariff` мають бути скінченними та невід'ємними. Приклад `data/input.csv` містить коректні та помилкові рядки:

```text
Електроенергія;2026-09-01;145.5;4.32
Вода;2026-09-02;12.3;30.50
Газ;2026-09-03;помилка;7.96
```

## Показники

Для коректних записів обчислюються сумарне споживання, загальна вартість (`value * tariff`), найбільше споживання та середнє споживання. Усі числа мають два знаки після крапки та форматуються незалежно від локалі.

## Збірка і запуск

Потрібна Java 21 або новіша. Maven Wrapper завантажує Maven автоматично.

```bash
# Ubuntu/macOS
./mvnw test
./mvnw verify
./mvnw package

# Windows PowerShell
.\mvnw.cmd test
.\mvnw.cmd verify
.\mvnw.cmd package
```

Запуск зі значеннями за замовчуванням:

```bash
java -jar target/lab01-1.0.0.jar
```

Додаткові режими:

```bash
java -jar target/lab01-1.0.0.jar --help
java -jar target/lab01-1.0.0.jar --version
java -jar target/lab01-1.0.0.jar --input path/to/input.csv --output out/custom-report.txt
```

За замовчуванням читається `data/input.csv`, а звіт записується в `out/report.txt`.

### Кодування консолі Windows

Якщо PowerShell показує українські символи як `????`, перед запуском увімкніть UTF-8:

```powershell
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
java -jar target\lab01-1.0.0.jar
```

Файл звіту програма завжди записує в UTF-8 незалежно від кодування консолі.

## CI/CD

GitHub Actions запускає `verify` і пакування на `ubuntu-latest`, `windows-latest` та `macos-latest`, використовує кеш Maven і публікує JAR як артефакт з номером workflow-запуску в назві. SpotBugs запускається у фазі `verify`.

Версія програми `1.0.0` є версією вихідного коду і фіксується Git-тегом `v1.0.0`. Номер CI-збірки є окремим послідовним номером конкретного запуску workflow: він змінюється для кожного запуску й не описує сумісність або зміст версії програми. У CI номер передається до програми через `-Dci.build.number` і показується в `--version`.
