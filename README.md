# Лабораторна робота №1: Комунальні показники

Консольна Java-програма читає показники комунальних послуг, пропускає хибні записи з поясненням причини, обчислює показники та створює звіт у консолі й файлі. Розширення в лабораторній роботі №2 описано в окремому розділі [«Лабораторна робота №2»](#лабораторна-робота-2-клас-сутність).

## Формат входу

Файл кодується UTF-8. Один запис займає рядок, поля розділені `;`:

```text
meter;date;value;tariff
```

Дата є текстом у форматі `YYYY-MM-DD`. Числа `value` і `tariff` мають бути скінченними та невід'ємними. Приклад `data/input.csv` містить коректні та помилкові рядки:

```text
Електроенергія;2026-09-01;145.5;4.32
Вода;2026-09-02;12.3;30.50
Газ;2026-09-03;помилка;7.96
```

## Показники

Для коректних записів варіанта 9 обчислюються сумарне споживання, загальна вартість (`value * tariff`) і найбільше споживання. Усі числа мають два знаки після крапки та форматуються незалежно від локалі.

## Збірка і запуск

Потрібна Java 25 або новіша. Maven Wrapper завантажує Maven автоматично.

```bash
# Ubuntu/macOS
./mvnw test
./mvnw verify
./mvnw package

# Windows PowerShell
.\mvnw.cmd test
.\mvnw.cmd verify
.\mvnw.cmd package
```

Запуск зі значеннями за замовчуванням:

```bash
java -jar target/lab01.jar
```

Додаткові режими:

```bash
java -jar target/lab01.jar --help
java -jar target/lab01.jar --version
java -jar target/lab01.jar --input path/to/input.csv --output out/custom-report.txt
```

За замовчуванням читається `data/input.csv`, а звіт записується в `out/report.txt`.

### Кодування консолі Windows

Якщо PowerShell неправильно відображає українські символи, перед запуском
можна увімкнути UTF-8:

```powershell
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
java -jar target\lab01.jar
```

Вхідний файл і звіт програма обробляє у кодуванні UTF-8.

## CI/CD

GitHub Actions запускає `verify` і пакування на `ubuntu-latest`, `windows-latest` та `macos-latest`, використовує кеш Maven і публікує JAR як артефакт з номером workflow-запуску в назві. SpotBugs запускається у фазі `verify`.

Єдине джерело версії програми — `pom.xml`. Під час Maven-збірки значення автоматично підставляється у ресурс програми та показується параметром `--version`. Номер CI-збірки є окремим послідовним номером конкретного запуску workflow: він змінюється для кожного запуску й не описує версію продукту. У CI номер передається до програми через `-Dci.build.number`.

## Лабораторна робота №2: клас-сутність

У лабораторній роботі №2 запис показника замінено незмінним класом-сутністю `UtilityRecord`; формули показників і формат звіту з лабораторної роботи №1 збережено. Повний опис і порівняння поведінки наведено в [REPORT.md](REPORT.md).

### Клас-сутність і валідація

`UtilityRecord` — `final`-клас із `private final`-полями `meter`, `date`, `value` і `tariff`, без сеттерів. Конструктор відхиляє:

- `null`, порожню або пробільну назву лічильника й дату;
- дату не у форматі `YYYY-MM-DD`;
- від'ємні, `NaN` та нескінченні `value` і `tariff` (нуль допустимий).

Статична фабрика `UtilityRecord.fromCsv(String)` перевіряє, що в рядку рівно чотири поля, перетворює числа та створює об'єкт через цей конструктор, тому правила не дублюються. Помилка розбору містить причину; номер рядка додає цикл читання в `ApplicationController`, а некоректний запис не потрапляє до списку й не змінює статистику. `toString` використовує `Locale.ROOT`. Для підсумків використовується незмінний record `UtilityReportCalculator.Summary`.

### Структура програми

Параметри командного рядка розбирає `CommandLineParser`, а `ApplicationController` керує читанням, обробкою записів і створенням звіту. `Main` лише координує запуск і повертає код завершення. Версія визначається у `pom.xml` і автоматично додається Maven до ресурсу збірки, який використовує `--version`.

### Запуск

Команди збірки й запуску ті самі, що наведені вище у розділі «Збірка і запуск». Перевірка якості лабораторної роботи №2: `mvnw.cmd -B clean verify package`, після чого `java -jar target/lab01.jar --version` виводить `2.0.0`.
