# Звіт до лабораторної роботи №1

## Тема і варіант

- Предметна область: комунальні показники.
- Варіант: `meter:String; date:String; value:double; tariff:double`.
- Система розробки: Windows, Java 21, Maven.

## Реалізація

Програма читає `data/input.csv` через `Path` і явне кодування UTF-8. `UtilityRecordParser` перевіряє кількість полів, назву лічильника, текстову дату `YYYY-MM-DD`, а також скінченність і невід'ємність числових значень. Неправильний рядок не зупиняє обробку: у звіт додається його номер і причина пропуску.

`UtilityReportCalculator` окремо обчислює чотири показники: сумарне споживання, загальну вартість, найбільше та середнє споживання. `ReportFormatter` форматує числа через `Locale.ROOT` з двома знаками після крапки. `FileReport` відповідає за читання і запис файлів.

## Збірка і запуск

```text
./mvnw test
./mvnw verify
./mvnw package
java -jar target/lab01-1.0.0.jar --input data/input.csv --output out/report.txt
```

У Windows використовується `mvnw.cmd`. Перевірені також режими `--help` і `--version`.

## GitHub Issues і Pull Request

Для здачі роботи потрібно створити публічний репозиторій з назвою, що містить номер роботи та прізвище, додати Issue для налаштування, розбити роботу на Issues з мітками `infra`, `feature`, `bug`, `docs` та пов'язати виправлення у Pull Request через `Closes #N`. Форми Issues і шаблон Pull Request збережені в `.github`.

## Тестування, CI і артефакти

Локально виконуються `test`, `verify` і `package`. JUnit 5 перевіряє коректний український запис, чотири показники, помилкове число, від'ємне значення, неправильну дату, неправильну кількість полів і форматування. SpotBugs запускається під час `verify`.

Workflow GitHub Actions використовує матрицю `ubuntu-latest`, `windows-latest`, `macos-latest`, кеш Maven-залежностей і Maven Wrapper. Після успішного пакування JAR публікується як артефакт з номером запуску в назві. `--version` виводить версію `1.0.0` і CI build number.

Версія джерельного коду та номер CI-збірки не є взаємозамінними. Версія `1.0.0` позначає стан і сумісність програми та фіксується тегом `v1.0.0`; CI build number лише ідентифікує конкретний запуск автоматичної перевірки й може зростати без зміни версії програми.

## Академічна доброчесність

Під час виконання лабораторної роботи використано GitHub Copilot як інструмент консультації та перевірки коду. Усі результати збірки, тестування та роботи GitHub Actions були перевірені власноруч. Виконавець розуміє структуру програми та може пояснити її основні компоненти на захисті.

## Висновки

У результаті виконання лабораторної роботи створено консольну Java-програму для обробки комунальних показників. Програма читає UTF-8-файл, перевіряє коректність записів, пропускає помилкові рядки з поясненням причин, обчислює чотири показники та формує звіт у консоль і файл.

Також налаштовано Maven-проєкт, JUnit 5, SpotBugs, Maven Wrapper, створення виконуваного JAR-файла та GitHub Actions для Ubuntu, Windows і macOS. CI успішно виконує тести, статичний аналіз і пакування, а JAR-файли публікуються як артефакти.

Створена програма є основою для лабораторної роботи №2, у якій прості рядкові структури можуть бути замінені повноцінними класами предметної області.
